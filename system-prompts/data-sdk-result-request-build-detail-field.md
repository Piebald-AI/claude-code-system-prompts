@internal How the request_build phase of time_to_request_phases_ms was spent: assembling the request from the normalized messages up to its dispatch. Read it as tool_schema_build_detail: the nine values from records_ms to other_ms, in the order the code runs, add up to the phase exactly. The phase pauses while the first attempt's client is made (client_creation), and that pause is in no part. records_ms: from the phase's start to the check for fallback blocks: recording for the conversation what this request sends (copies of tool inputs, tools surfaced or deferred) and setting up what the retry handlers share. system_ms: that check, a short hash of the first user message and the attribution header that carries it, the cache lifetime and the system prompt's blocks. headers_ms: comparing the tools and the system prompt with what was first sent and, where they changed and the model is told, passing that notice on and building the messages a second time with it; then effort, fast mode, up to two waits for the permission context, the beta headers that stay on for the conversation, and setting up the handling of the API's context hints, whose code can load here on a process's first request. cache_break_record_ms: recording the prompt's state (recordPromptState) so that a later prompt-cache break can be explained: a digest of every message and hashes of the system prompt and the tool list; where the session keeps that state on disk, a process's first request also reads the file and every request queues its write. plans_ms: from there to the end of the request builder's definition, such as defining the first retry handlers, planning which tool results to clear and opening the request's tracing span. retry_setup_ms: from there to the making of the first attempt's client, such as defining the rest of the retry and fallback handlers. sent_build_ms: building the parameters that are sent, for every attempt before the first dispatch (normally one). record_attempt_ms: from there to the moment the request is recorded as sent: reading the values for the analytics event that logs the request (the event itself is sent after the dispatch and is timed nowhere), the debug log's detail, and the attempt's record, such as the check of the sent prefix and the request's capture. other_ms: as in tool_schema_build_detail. Three more members each measure one stretch inside the sent build; they lie within sent_build_ms, need not add up to it, and are not part of the sum. sent_build_safety_context_ms: assembling the context for the server-side safety check; near 0 where the session does not ask the server to check tool calls. sent_build_cache_breakpoints_ms: the last clean-up of the messages before sending, placing the prompt-cache breakpoints, which makes a new copy of every message, and the scans for cache markers that follow. sent_build_surrogate_scan_ms: reading every string of the body for lone UTF-16 surrogates, and the scrub where one is found. Nothing after the turn's first dispatch is timed (a retry, a later request), and nothing of a subagent's request or a side query. Present where time_to_request_phases_ms has request_build.
