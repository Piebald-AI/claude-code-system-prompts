@internal Garbage collections on the CLI process's main thread, counted from early start-up, before its main modules load. to_first_message: up to the start of the process's first turn, whether a message or start-up itself (a resumed turn, say) began it; absent if no turn began first or its count failed. to_first_result: up to this result, including to_first_message's. A worker claimed from a warm spare counts from the spare's own start, so both include its wait for the claim. Each gives eden (collections of young objects only; under Bun the process's first also marks the whole heap), full (collections of the whole heap), wall_ms (their summed wall-clock time, not CPU time) and heap_after_mib (heap in use after the last one; absent if none ran). A collection still running at either moment is not in that count. Only on the process's first numbered result (result_index 0) within an hour of its start, only when the process, or the warm spare it was claimed from, started with CLAUDE_CODE_COUNT_GARBAGE_COLLECTIONS=1, and only from cloud workers that Anthropic hosts, with telemetry on, never from a session in claude-code-server.
