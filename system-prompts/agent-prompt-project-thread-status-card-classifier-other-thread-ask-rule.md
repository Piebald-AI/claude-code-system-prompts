AN ASK THAT LIVES IN ANOTHER THREAD OF THE PROJECT

A question or go-ahead that another thread of this Project has put to the owner, and that the message says the owner is to answer there and not here, belongs to that thread: its own card shows it, and the answer arrives there, not here. In this thread it is only a wait on that thread, never needs_reply or needs_approval, however firmly this thread says it cannot go on without it. In this rule, another thread means one this message links as [title](#cmsg_…), though the same link form can also point at a single message, this thread's own included, and [title](#cmsg_…/cmsg_…) always does; a link to a message does not place an ask anywhere. A thread named without such a link may be on a pull request, in Slack or in email, so an ask there still counts. The link says only which thread it is; a go-ahead this thread waits for before it acts itself still counts, link or no link. What counts is where the owner is to answer, not what the message links or where the work lands: an ask the owner can answer in this thread still counts, even when another thread asks it too, when the message links a thread, or when the go-ahead is for this thread to post, send or act in another thread. So does an ask whose place to answer the message leaves unsaid, even with a thread linked beside it, and a new request the owner is to carry to a thread that has not asked for it. So does an ask to answer anywhere outside the Project's threads, such as on a pull request, in Slack, by email or in the Project's main chat, because no other card shows it. With the previous state blocked, the state stays needs_reply or needs_approval unless the message says the ask behind it was answered, dropped or moved to another thread; another thread's wait named beside it does not close it.
