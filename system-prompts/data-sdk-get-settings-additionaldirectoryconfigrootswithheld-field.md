@internal The added folders (dir, as given) whose configuration root, named by additionalDirectoryConfigRoots, supplied less than all of its configuration at a read made for this answer: reads "nothing" = the folder supplies no skills, commands, agents or plugin settings at all; "root_less_entries" = the root is read but entriesWithheld distinct entries under its .claude (a file or folder; inside a skill package, the whole package) are left out. root is the named root, or null where it was unusable or the settings carrying the key were dropped. reason is the main one, as a token: root_unusable (not an absolute, local, existing folder), match_lost (the link that matched the folder to its key no longer does), root_moved (the root is gone, or a link or another directory now stands at it or at a folder above it), inside_writable (the root lies inside a folder a sandboxed command may write; listed only where the root has a .claude), entry_is_link (a link or hard-linked file where none may be), unreadable (an entry could not be examined), too_many_entries (its .claude holds more entries than are examined, 20,000), settings_dropped (the settings that carried the key were invalid as a whole; then every folder they left without configuration is listed, named or not). Other folders whose root is read whole, or that no entry names, are not listed; absent or empty means nothing to report. Not sent on a connection whose answers may be stored off the machine, nor where the session withholds its folders. docs/desktop-host-contract.md D176.
