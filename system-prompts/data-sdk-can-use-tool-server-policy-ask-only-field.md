@internal Sent with decision_reason_type 'rule', for an MCP tool's ask that has none, for the default prompt of Write or Edit with no reason type, and for that of Read, Write or Edit with 'workingDir' and the plain outside-the-working-directories decision_reason. true = when the frame was built, nothing asked for a person on this call but the default prompt for a tool that no rule allows and, at most, a tool policy that the host itself pushed (permission_policy 'always_ask'): no other ask rule that the permission check applies to the call, no hook's or plugin's ask, no PermissionRequest hook, no organization ceiling, no plan-mode floor, no safety check, no ask or veto on a standing grant of the tool's own, no auto-mode classifier active for the call. false = something else did, or may have. It says nothing of WHY the host pushed that policy, which only the host knows; nothing of whose server the tool is (see mcp_server), so a host answers only for a tool that it holds a person's grant for (a file tool apart, below); and nothing of what changes after the frame is sent. For a file tool it says nothing of where the path lies, so a host answers only for a path that it has judged itself. Absent on other reason types, on any other tool's ask without a reason type (Read's included), wherever a request is listed, mirrored or passed on again (pending_permission_requests), and from older versions.
