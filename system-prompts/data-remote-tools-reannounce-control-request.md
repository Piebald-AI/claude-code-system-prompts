@internal A replacement worker asks the attached client that serves this session's tools to announce it, when a call names a machine its roster lacks. Not addressed to an instance: the worker knows none. A client that serves the machine announces, overriding once what it believes the worker already holds; it honours one ask per epoch, another only when the announce that one made failed or went unanswered, and at most one per ten seconds, and does nothing for an ask it cannot date or read, or whose sender it would refuse a tool call from. Any other client, and a client that predates the request, does nothing or error-replies, and the worker reads no reply: it withdraws the request with control_cancel_request when its wait ends. A worker that the desktop app hosts also asks the app this way, as it starts and at a turn's start while it holds no host, and withdraws none of those asks. The session service answers such an ask with the error device_announce_refused where it would refuse the app's announce now, or device_stream_closed where the device's stream to it is closed; the worker reads either reply to its newest ask alone, and it ends that turn's wait for the announce.
