@internal How the turn went about its memory check, the request that asks the session server whether the account's memory has changed. Present, in a cloud session that makes such checks, on the result of a turn that was handed to the model loop, stopped or not; absent on a local command's. A turn that will wait for the answer can first be held until the request is sent, which the memory_send_wait phase times. flag: the hold's feature flag as the turn started (1 on in claude-code-server, 2 on in every cloud worker, 0 for anything else); absent where the process's flags were not fresh. hold: off (not on for this worker), not_due (the turn was not expected to wait, or that could not be told), nothing_to_send (the request had already been sent or answered, none was due, or it is one the server may hold, which the wait replaces), or how the hold ended: sent, cap (its time limit came first), abort (the turn was stopped), failed (the request ended before it was sent). wait: went_on (the turn did not need its own check's answer, took one that was asked for ahead of the message, or the server had stopped the checks), answered, cut (the wait for the answer ran out), unanswered (the request was refused or failed); absent where the turn was stopped first or never came to that wait. wait is decided the same way with the hold on and off. requests: how many such checks the process has started since the last turn that reported this number, whether at start-up, ahead of the message, after the previous turn or for this turn, counting one refused before it was sent; 9 means 9 or more; present with wait.
