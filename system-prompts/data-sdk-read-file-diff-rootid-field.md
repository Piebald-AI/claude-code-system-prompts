The `rootId` of the get_workspace_diff answer that `path` came from, sent back unchanged. If the directory the session would diff now is not the one that answer's paths are relative to, or there is none, the read is refused with `read denied: <path>` and the error_code stale_root_id: the directory has changed, or the session's process has restarted. Ask for the diff again rather than resending. Where the directory could not be looked up (get_workspace_diff then answers diff-failed too), the read is refused with `read denied: <path>` and no error_code. Otherwise the read is served as a diff_root read without `rootId` would be. It is served also in a session whose diff follows the shell's cwd between several repositories, where a diff_root read without `rootId` is refused. A CLI that has `rootId` but predates these two rules answers stale_root_id where the directory could not be looked up, and refuses a matching read in such a session with `read denied: <path>` and no error_code. Leave it out when the answer had none: null is refused as a malformed anchor, with no error_code. A CLI that has `anchor` but predates `rootId` ignores it.
