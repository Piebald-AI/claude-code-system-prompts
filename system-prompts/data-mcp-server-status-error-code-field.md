@internal Why a row is not connected, where a host can act on it. On a 'failed' row: CLAUDEAI_BEARER_REJECTED (a claude.ai connector rejected the claude.ai login — sign in again), FIRST_PARTY_AUTH_REJECTED (a first-party Anthropic server rejected its credential — the claude.ai login, or for the Claude Design server its /design-login authorization; the row's error names which sign-in fixes it, except over a transport that stores its frames, where it reads 'Connection failed'), APPROVAL_REQUIRED (a project-scoped server awaiting the user's approval), CLAUDEAI_CONNECTORS_DISABLED (a claude.ai connector that the desktop app handed over in process, left out because a managed or served source sets disableClaudeAiConnectors: nothing to reconnect). On a 'failed' or a 'needs-auth' row: CLIENT_REGISTRATION_UNAVAILABLE (the last look at the server's authorization server, under 30 days ago, found no way to register a client, so mcp_authenticate is expected to fail; the row keeps this value until the server is dialed again, for example by mcp_reconnect or a completed sign-in, so keep sign-in and reconnect available). Absent in every other case; new values are additive.
